# 梭了啦 P2：全桌都在看你笑話（事件導演、轉播、賽後戰報）

分支：`feature/laststand-p2-director`（從 P1.6 開發分支 `c13f9c0` 開出來）。**沒有合併、沒有部署**，正式網站還是 P1.5（`1d3d96d`）。

## 一句話

牌桌多了一組「轉播」：聊天室、主播、公告、四個節目的小卡、第四墩後一次中場節目；打完有一份可以複製分享的賽後戰報。**全部只演，不改任何規則、籌碼、下注上限、勝負，也不加座位或觀眾連線。**

## 怎麼運作

```
伺服器送來的牌桌（LSView，只有自己看得到的部分）
   │ publicOf()：拿掉手牌、自己鎖的牌、讀心結果、讀心紀錄、能做的動作 → 只剩雙方都看得到的事
   ▼
analyze()（純函式）：從第 1 墩掃到現在 → 敘事事件 Beat（穩定 id）＋每個人的習慣統計＋下注壓力 1～4
   ▼
Director（每一場一個，用對局編號 gid）：只挑「新的」事件 → 選文案（先篩條件、再用 gid 決定起點輪著用）→ Cue
   ▼
Stage（純邏輯排程，時間由外面給）：優先級、頻道冷卻、字幕最多兩則、小卡一次一張、舊新聞丟掉
   ▼
lsmedia.ts（畫面）：字幕條、節目小卡、壓力氛圍；結算時 buildReport() → 賽後戰報
```

- **雙方一樣**：同一場、同一份公開紀錄、同一個 gid → 兩支手機選到一模一樣的句子（不用伺服器、沒改協定）
- **重新整理／斷線回來**：新的導演先「不出聲」把整場重跑一次（記住用過哪些句子），之後接著演；舊新聞不重播（伺服器整份重送 resync 也一樣）
- **只講真的發生的事**：每一則都是從公開紀錄推出來的；「雙方各押」只在接戰之後；翻轉後輸、同點、逆轉、退款這類結果只在那一墩結算之後；加注「提出」的金額跟「雙方都押進去」的有效下注分開講
- **不外洩**：導演拿不到任何隱藏資訊；翻開的牌才會被提到（300 場模擬每一步檢查）

## 做了什麼

### P2-A 事件導演（`src/laststand/director/`）

| 檔案 | 內容 |
|---|---|
| `types.ts` | `PublicMatch`、`Beat`（敘事事件）、`BeatKind`（narrative／challenge／social）、`Cue`（一則演出）、`Channel`、12 個 `ProgramId` |
| `config.ts` | **可調資料**：優先級（100 結果／逆轉、90 決勝梭哈被接、80 重大反加、60 連續行為、40 普通、20 聊天）、哪些要等結算、哪些可以當戰報素材、事件 → 節目、12 個節目註冊（啟用 4＋中場用的突發新聞）、節奏（字幕 2 秒、重要 3 秒、小卡照行數 2.4～4.2 秒、中場 3 秒、冷卻、每步最多 1 張小卡＋3 句）、壓力門檻 |
| `analyze.ts` | `publicOf()`、`analyze()`：38 種敘事事件；每人統計（加注、反加、連續加注墩數、棄牌、連續棄牌、梭哈、接梭哈、讀心、讀心後棄牌、翻轉結果、保命結果、贏輸、連輸）；整場（最大疊池、最大有效下注、領先換手）；`levelOf()` 下注壓力 |
| `lines.ts` | 新寫的轉播文案（P2-001～P2-832），含你指定的 13 句 |
| `director.ts` | `Director.update(公開資料, silent)`、文案選擇（新文案＋V2 原文一起當候選）、契約公證處開場、中場節目（照真實戰況挑：連續加注／落後很多／疊池／專家分析）、豪言回放（每場最多一次）、`hash()`、`fill()` |
| `scheduler.ts` | `Stage`：push／step／skipCard／block／clear |
| `report.ts`、`report-lines.ts` | 賽後戰報（P2-C） |

觸發條件的幾個重點：
- 「連續三墩加注」＝三個**連續的不同墩**各自加注過（同一墩加注再反加不算兩次）；之後第 4、5…墩另外有「連續 N 墩」
- 「讀心後棄牌」要同一墩、同一個人先讀心再棄牌
- 「加注很多次的人第一次棄牌」（記仇）：加注 ≥ 3 次或曾經連續 3 墩加注
- 「逆轉」比的是這一墩結算前後的真實持有（手上＋疊池裡自己的出資），平手變領先不算
- 中場節目：第 4 墩結算、比賽還沒結束才播，最多一次；第四墩前有人歸零就不播；那一墩的其他小卡讓位給中場

### P2-B 牌桌轉播（`src/client/lsmedia.ts`）

- **字幕條**：蓋在最上面的標題列（跟原本的提示條同一區），最多兩則、約 2 秒淡出；左邊留「3/9」小標（AI 測試是「測試・3/9」），墩數不會消失；新的那則要兩行就先收舊的（不切半句）
- **節目小卡**：放在「對手、方向、賭盤、每墩紀錄」下面、底部固定區上面的空位；對白一行一行出來；點一下略過（不會送出任何動作）；底部區長高（輪到你）、賭盤翻牌、紀錄展開都會重新量，**空位不夠就縮成標題列一行**（寧可少演，不縮牌桌）
- **規則提示條優先**：原本的提示條（對手翻轉、保命、讀心、梭哈、退款、錯誤）出現時，字幕先讓位
- **下注壓力**：四周暗紅，1～4 級（只動 opacity；第 4 級很慢地呼吸；減少動態時不呼吸）
- **設定**：「梭了啦轉播：正常／精簡（只播優先級 ≥ 60）／關閉」
- **減少動態**（系統設定或動畫效果關閉）：不位移，只淡入淡出
- AI 測試局、朋友連線都能用（同一套程式）

### P2-C 賽後戰報

結算面板（照規則打完：九墩或有人歸零）多一行戰報標題＋「看賽後戰報」。認輸、斷線逾時沒有完整戰報。

| 段落 | 來源 |
|---|---|
| 標題 | V2 賽後事件的標題 vs 新寫的條件標題（大逆轉、提前收工、連續加注、讀心後棄牌、疊池、翻轉後輸、棄牌很多），照分數挑 |
| 結果 | 九墩打完雙方持有／第幾墩誰歸零／平手 |
| 關鍵一注 | 全場「雙方都押進去、而且翻了牌」最大的一注（含比大／比小、翻開的牌）；不是提出的加注金額 |
| 本場最荒謬 | 讀心後棄牌 > 翻轉後輸 > 加注很多次後第一次棄牌／連續 N 墩加注 > 面對梭哈棄牌／保命那墩自己贏 > 疊池擴大／連續三墩棄牌 > 連輸三墩 |
| 記仇小本本 | 雙方習慣，每人最多兩條、全部最多三條，兩邊都有就各至少一條 |
| 契約清算 | 敗者交出什麼（原樣）、雙方豪言（兌現／已列入紀錄／保留解釋空間）、僅供遊戲敘事 |
| 賽事單位聲明 | V2 長篇原文（先跟標題同一件事） |
| 結語 | V2 punchline（跟標題同一件事，不然用一般收尾），都沒有才用新寫的 |

- 同一場一定同一份；雙方一字不差；可以複製成純文字（AI 測試會加「單人測試｜不計正式戰績」）
- 畫面一律 `textContent`；玩家填的字原樣放進去
- V2 文案（`copy/laststand_v2_copywriting.json`）**一字未改**（sha256 測試照舊）；`summarize()` 只是改成接受公開紀錄（`history`／`result`／`folded`），棄牌牌面只有雙方同意揭露才看，這裡不看

## 已知限制

- 文案輪換是「這場用過的盡量不重複」，跨場不記；同一個對局編號一定選到同樣的句子
- 認輸、斷線逾時結束的比賽沒有完整戰報（只有原本的結算面板）
- 文案口味（V2 的冷面／聊天室／發癲）目前固定「聊天室」；房間共同選擇留到之後
- 轉播字幕在小螢幕上偶爾會先收舊的那則（為了不切半句）

## 給 P3 之後用的介面

- **事件**：`analyze(PublicMatch)` → `Beat[]`＋`MatchStats`＋`Pressure`；新事件加在 `BeatType`，優先級／結算／戰報素材在 `config.ts`
- **事件種類**：`BeatKind` 保留 `challenge`、`social`；**會影響規則的事件（挑戰、交換籌碼、改上限、強制換牌、真心話大冒險）將來一定要由伺服器權威引擎驗證與結算**，這裡的資料只能拿來演
- **節目**：`PROGRAMS` 已註冊 12 個（氣象預報、稽核調查局、客服中心、專家講座、街頭訪問、情感諮商、頒獎典禮先停用）；啟用＝改 `enabled`＋在 `BEAT_PROGRAMS` 指定事件＋在 `lines.ts` 寫 `card(...)`
- **演出**：`Cue`（純文字、頻道、優先級、壓力、可略過）；`Stage` 不碰 DOM，可以拿去別的畫面（例如觀眾畫面）
- **戰報**：`buildReport(PublicMatch, Cast, gid, { taste, footer })` → 分段＋純文字
- **驗收掛鉤**：`globalThis.__hbCast()`（最近演過什麼、壓力、排隊數；只有畫面上本來就會出現的字）
