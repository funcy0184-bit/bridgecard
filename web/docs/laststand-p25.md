# 梭了啦 P2.5：遊戲體驗重構（規劃與 P2.5-A 規格）

分支：`feature/laststand-p25`（從 P2 上線後的開發分支 `76f0b92` 開出來；正式網站是 `8447325`）。**只規劃、還沒動程式；不部署。**

核心目標：讓玩家覺得自己在**打牌**，不是在填網頁表單。

## 0. 現況分析（看過程式碼和畫面）

### 0.1 畫面結構（`public/index.html` 的 `#lstable`、`src/client/lstable.ts`）

```
#lstable（可捲動的直欄）
├─ header.lsbar      第幾墩＋底注上限＋單人測試標籤＋選單鈕；P2 的轉播字幕蓋在這裡（#lsTicker）
├─ #lsOpp            對手：名字、角色、狀態、籌碼、「剩 N 張：大x・中y・小z」、技能文字
├─ #lsDir            本墩「比大／比小」大字＋下一墩
├─ #lsPot            雙方已投入（文字）、疊池（文字）、上一墩結果（#lsReveal：兩張小牌＋一句話）
├─ details#lsLog     每墩紀錄（展開會把版面往下推）
├─ #lsCast           P2 節目小卡（fixed，量空位放）
└─ #lsDock（sticky 底部）
   ├─ #lsMe          自己：角色、籌碼、剩幾張大中小、技能
   ├─ #lsTurn        一句「輪到誰／做什麼」
   ├─ #lsHand        9 張牌一排、每張下面寫「大／中／小」；鎖了的牌留在手牌裡標「已鎖」
   ├─ #lsRisk        輸贏試算（2 行）
   └─ #lsActions     按鈕（innerHTML 每次重畫）＋說明小字
```

- **畫法**：`lsView()` 每收到一個新的牌桌（LSView）就整個 `render()`：手牌 `replaceChildren`、按鈕 `innerHTML`。**沒有持久的牌／籌碼節點**，所以沒辦法做「這張牌從手上飛到桌上」這種動畫
- **事件**：伺服器送 `ack → room → lsEvent → lsState`。lstable 目前只拿事件來跳提示條（對手翻轉、保命、讀心、梭哈、退款、歸零）
- 可用的公開事件：`TrickStart`、`Flip`、`Safeguard`、`Locked`（誰鎖了，不含牌）、`LockedCard`（**只送給本人**）、`Ante`、`Check`、`Raise`、`Call`、`Fold`、`Insight`、`Showdown`（翻牌：雙方牌面）、`FoldReveal`（棄牌：只有大中小）、`Settle`、`PoolAdd`、`PoolRefund`、`Eliminated`、`MatchOver` → **做動畫需要的資訊都已經有，不用改協定**
- 斷線回來（resync）只給最新快照、不補播 → 動畫一律「看到事件才演、快照只擺好位置」

### 0.2 動畫、音效、效能（已經有、可以直接用）

| 模組 | 現有能力 | 梭了啦有沒有用 |
|---|---|---|
| `fx.ts` | `fly`（弧線飛行、半路翻面）、`pin`、`land`（壓縮回彈）、`flipTo`、`shockwave`、`punch`、`glow`、`countUp`；動畫強度／加快／減少動態設定 | 只用 `cardEl` |
| `impactfx.ts` | 經典出牌的「拉起 → 甩出 → 落桌 → 回彈」三段（`pullUp`、`slamFly`、`contact`） | 沒用 |
| `sound.ts` | 合成音效：`lift`、`slap`、`land`、`faceUp`、`swish`、`boom`… | 沒用；**沒有籌碼音** |

| `tension.ts` | 壓力氛圍、聚光 | P2 用自己的壓力暗角 |

### 0.3 問題（對照 `p25/base-ls-*.jpg` 現況圖；經典牌桌 `p25/base-classic-390.jpg` 是美術方向參考）

1. **沒有「桌子」**：中間只有大字方向和一條「已投入」文字，牌和籌碼都不在桌上；底部固定區占畫面 55～60%
2. **表單感**：面對加注時最多 6 個按鈕＋2 行試算＋1 行說明，全部一樣大
3. **鎖了的牌還在手牌裡**（標「已鎖」），沒有「把牌蓋到桌上」的動作
4. **籌碼只是數字**：底注、加注、接戰、收底池都沒有東西在動
5. **大中小說太多次**：對手「剩 9 張：大3・中3・小3」、自己同一句、每張牌下面又寫一次、讀心按鈕又寫一次
6. **流程不聚焦**：輪到誰、要做什麼、試算、提示四處都有字
7. **轉播搶位置**：字幕蓋標題列、小卡塞在中間空位；小螢幕常常沒空位

### 0.4 測試覆蓋（重構時要一起改）

- 依賴 lstable 結構的瀏覽器測試：`laststand-ui`、`laststand-layout`（六種大小 × 每個階段：重要資訊都在畫面裡、沒被底部區蓋住）、`lsai-ui`、`p15-ui`（提示條不蓋對手）、`p2-cast`（量 `#lsOpp`、`#lsDir`、`#lsPot`、`#lsLog`、`#lsDock`、`#lsBar` 的位置）
- 它們用到的選擇器：`#lsActions [data-a=…]`（全部按鈕）、`#lsHand .lscard`、`#lsMyChips`、`#lsOppChips`、`#lsOppCounts`、`#lsDirBig`、`#lsDirNote`、`#lsStage`、`#lsRisk`、`#lsTurn`、`#lsTrick`、`#lsReveal`、`#lsLog`、`#lsMenuBtn`、`#lsTestTag`、`#lsOppName`
- **策略**：`data-a` 按鈕名稱、`__hbLS()`、`__hbCast()` 驗收掛鉤保持不變；其他 id 盡量沿用，新增區塊用新 id，測試跟著改；不碰規則、伺服器、AI、導演的單元測試

### 1.1 測試制度：風險導向三級（2026-11-13 起，P2.5-B～F 都照這個做）

目的：不做沒必要的重複測試，把時間花在遊戲體驗上；核心規則和連線安全照樣守住。這一節就是測試的規矩，不另外開一套開發週期。

**L1 日常開發**（每次小改之後）

1. 跑這次改到的單元測試（`npx vitest run test/<相關>.test.ts`）
2. 跑直接受影響功能的必要測試
3. 有改 UI：挑**一個代表尺寸**（iPhone 13 390×664）做快速冒煙；排版有改再加 320×568
4. 不用每次跑完全部單元測試、所有尺寸、多場連線對局、全部瀏覽器測試
5. **例外：一定要追加安全測試**
   - 規則、下注結算：`laststand.test.ts`、`laststand-lifecycle.test.ts`
   - 隱藏資訊：`laststand.test.ts` 的視角測試；`p25-a.mjs` 的「翻牌前看不到對手的牌」
   - 網路協定、狀態同步：`laststand-room.mjs`、`two-sockets.mjs`、`reconnect.mjs`

**L2 階段完成**（A～F 每段做完、交驗收前）

1. 這一段主要功能的測試（例如 B 段的動畫驗收腳本）
2. 一場代表性的完整 AI 對局（`p25-a.mjs` 的 iPhone 13 整場）
3. 跟修改內容直接相關的回歸測試
4. 必要的斷線、快速連點或狀態恢復測試
5. 手機尺寸以代表尺寸為主；這一段有改響應式排版才加跑 `laststand-layout.mjs` 的其他尺寸

**L3 完整回歸**（只在這四個時機跑）

- 時機：
  - 準備合併正式分支
  - 準備部署 Cloudflare
  - 重大架構、規則或網路協定變更
  - P2.5 全部完成、準備正式驗收
- 範圍：全部適用的單元、整合、連線、UI、轉播、六種尺寸加橫拿，以及重要的安全測試
- 不在約定的部署或合併流程裡，要先說明原因再跑

**共同規矩**

- 不刪既有測試；不為了過關放寬重要斷言
- 沒跑的寫「未執行」，沒觸發的寫「未覆蓋」，都不算通過
- 測試失敗：先分析原因，修好後只重跑失敗項目和直接受影響的測試
- 測試腳本本身不穩：修腳本或記下來，不無限制全部重跑
- 回報只寫四件事：測試等級、測試項目、結果、還沒執行的項目
- 真機人工驗收（`test/MANUAL-online.md`）不能用模擬手機取代
- 正式分支保護照舊：沒有你明確同意，不合併、不部署

## 2. P2.5-A 規格：牌桌骨架與視覺層級

### 2.1 這一段要做到

- 一眼看得出：**對手是誰、我手上有什麼、桌上押了多少、這一墩比大還比小、現在輪到我做什麼**
- 牌真的在桌上：雙方蓋下的牌放在綠絨桌的出牌位（對手在上、我在下）；翻牌結果也在桌上
- 底部只剩**一句問題＋主要按鈕**；次要資訊（試算細節、規則）收到「？」
- 六種手機大小都**不用捲動**；所有按鈕 ≥ 44px 高；什麼都不會蓋到手牌、按鈕、對手資訊、籌碼
- 這一段**不做動畫**（B、C 才做），但所有牌、籌碼、出牌位都改成**持久節點**，B、C 可以直接讓它們動

### 2.4 隱藏資訊規則（照舊、這一段要加測試）

- 對手的出牌位在翻牌前**只畫牌背**；DOM 裡不會有任何牌面資料（對手的牌 id 本來就不會在翻牌前送到手機上）
- 我蓋下的牌：牌背＋只有自己看得到的小標（「J♣」）；讀心結果只在我的畫面上顯示
- 棄牌的那墩：只公開大中小（跟現在一樣）

### 2.5 文字（A 段只動位置和層級；口語化在 D 段）

- 拿掉重複：自己的「剩 N 張：大中小」拿掉（自己的牌就在手上）；每張手牌下面的「大／中／小」字拿掉（D 段會給「?」說明和讀心時的提示）；技能從文字改成三個小圓章（用過的變灰）
- 對手的大中小留著（這是有用的情報），縮成「大2 中3 小1」
- 輸贏試算從 2 行縮成行動列的一行小字＋按鈕上的小字（接戰「補2」、棄牌「輸1」）；完整試算點「?」看
- 每墩紀錄：從展開式改成點「上一墩：…」打開的面板（不推版面）

### 2.6 P2 轉播在 A 段怎麼處理

- 字幕留在頂列中間一行（窄的時候只剩主播／公告，聊天室先不播）
- 節目小卡：牌桌上沒有空位了 → A 段一律用「標題列一行」的精簡模式；**正式的「旁邊一條＋重大事件進牌桌」在 E 段**
- 下注壓力暗角照舊；`__hbCast()` 照舊

### 2.7 技術做法

- **持久節點**：`lstable.ts` 改成「建一次、之後只更新」
  - 手牌：每張牌一個節點，用牌 id 當 key；鎖掉的牌從手牌**移到**我的出牌位（同一個節點，B 段直接加飛行動畫）

- **下注結束翻牌**：展示期間出牌位的 key 從 `back:*` 變成 `face:*` → 用正反兩面的 3D 翻面（`rotateY`＋光澤，素材 03），雙方錯開約 120ms；贏的那張金框＋`fx.punch`＋落桌重一點，輸的變暗；`sfx.faceUp`
- **收牌**：展示結束（`showUntil` 到期或點牌桌跳過）先播「兩張牌往贏家那邊收走」，播完再清空出牌區 → 下一墩
- **讀心**：對手蓋著的牌上掃一道光（素材 03 的掃描光）
- **原則**：只動 transform／opacity；事件來了才演、整份重送（resync）只擺好位置；減少動態＝直接到位＋淡入；低階裝置接 `perf.ts` 自動降級；所有動畫都不改規則、不擋伺服器的下一步

### 6.2 架構：牌桌演出導演（`lsstage.ts`）接管一墩的生命週期

A 段的骨架照用：手牌節點（`Map<牌, 按鈕>`）、出牌位的 key（`empty:ask`／`back:牌`／`face:牌`／`cat:分類`）、結算展示 → 清桌。B 段只換「誰決定什麼時候換畫面」：

| | A 段 | B 段 |
|---|---|---|
| 展示多久 | `SHOW_MS` 1.8 秒＋一個 `setTimeout` | **拿掉這個計時器**；由演出導演的時間軸決定：翻牌 → 判勝負 → 看結果 → 收牌 → 清桌 |
| 點牌桌略過 | 把 `showUntil` 歸零 | `stage.skip()`：直接跳到收牌（快速版）再清桌 |
| 誰在展示中 | `showing()` 看時間 | `stage.presenting()`：導演說了算（頂列、按鈕、手牌照 A 的規則跟著它） |

- **只有一條佇列、一個取消鍵**：事件進來只排「演出」，不直接動畫面。牌桌快照（`lsState`）照舊先擺好位置，演出再接手。
  - 例：對手蓋牌，出牌位的牌背先放好但藏著，飛到了才現身
- 演出用 Web Animations 的 `finished` 接下一段；整條時間軸只有「看結果」那一段需要等待，由同一個取消鍵管
- **伺服器說了算**：動畫只是表演，不擋伺服器的下一步。演出途中來了新的快照，照樣擺好位置，排在佇列後面演
- 動畫零件沿用經典模式已經調好的：
  - 抽離 `pullUp`、加速飛行 `slamFly`、落桌壓扁回彈＋接觸陰影 `contact`
  - 翻面、`punch`、拍桌聲 `sfx.slap`、翻牌聲 `sfx.faceUp`
  - 參考素材（`bridge-card-animations-lab`）只借節奏和 FLIP 的做法，不整包搬（它的全域變數會跟我們撞名）

### 6.3 一墩的演出表（數字是標準速度；「快速動畫」×0.6）

| 時機（觸發） | 演出 | 聲音 | 時長 |
|---|---|---|---|
| 點手牌 | 選牌升起：彈簧曲線往上 14px、微微放大、金邊；上一張落回 | `sfx.lift` | 約 220ms |
| 按「蓋牌」 | **按下的那一幀就開始動**：抽離 → 飛向我的出牌位（弧線、越近越快、半路翻成牌背）→ 落桌壓扁、回彈、接觸陰影 | 抽離 `swish`、落桌那一刻 `slap` | 約 490ms |
| 對手 `Locked` 事件 | 從對手名牌的牌背堆飛一張牌背到對手出牌位，落桌輕一點 | `slap`（輕） | 約 300ms |
| 結算（`Showdown`） | 兩張牌背翻成正面（3D 翻面），對手先、我晚 120ms | `faceUp` | 約 400ms |
| 判勝負 | 贏的那張金框＋`punch`；輸的變暗；同點兩張輕輕一頓 | 輕的落桌聲 | 約 250ms |
| 看結果 | 頂列、方向、結果標籤都是這一墩的（A 段已完成） | — | 到第 1.7 秒 |
| 收牌 | 兩張牌滑向贏家的名牌、縮小淡出；同點滑進中間疊池 | `swish` | 約 320ms |
| 清桌 | 出牌位清空、方向換下一墩，空的出牌位淡入 | — | 約 120ms |
| 棄牌（`FoldReveal`） | 牌背翻成「大／中／小」，接著照上面判勝負、收牌 | `faceUp` | 同上 |
| 整場結束 | 翻牌、判勝負後**不收牌**（最後一墩留在桌上），再出結算面板 | — | 照 A |

一墩結束總長約 2.1 秒（A 是 1.8 秒）；點牌桌可以略過。

### 6.4 安全與穩定

- **伺服器權威**：
  - 我的蓋牌是「先演、伺服器確認」：飛行約 0.3 秒，單機幾乎同時確認，連線通常也在落桌前確認
  - 慢一點的話，牌停在出牌位等確認
  - 被拒絕（例如狀態已過期）：牌飛回手牌、拒絕音、說原因
  - 規則判定全部照舊在伺服器
- **隱藏資訊**：
  - 對手的飛牌、出牌位一律只用牌背節點
  - 對手的正面只在 `Showdown` 事件或紀錄裡有牌面時才建立
  - 測試會掃整頁（包括特效層），翻牌前不能出現對手的牌面
- **快速點擊**：
  - 送出後 `busy` 鎖住按鈕（照舊），飛行中手牌不能再點
  - 連點「蓋牌」只會送出一次（指令編號去重照舊）
  - 演出中再點手牌、按鈕都不會打斷演出
- **斷線恢復**：
  - 整份重送（`resync`）或重新整理 → `stage.cancelAll()`：所有動畫直接到終點、飛行中的複製品移除、佇列清空，照快照擺好，**不重播**
  - 沒確認就斷線的蓋牌，以快照為準：有鎖到就顯示牌背；沒鎖到，牌回手牌
- **背景分頁**：頁面看不到的時候，佇列直接跳到終點（瀏覽器會暫停背景動畫，不然回來會一次補播一堆）
- **減少動態**（系統設定）或動畫「簡化」：
  - 不飛、不翻、不彈：直接到位，加 120ms 淡入
  - 看結果的時間不縮短；聲音照常
  - 動畫「關閉」：完全不演
- **效能**：
  - 只動 `transform`／`opacity`；飛行的牌放在特效層，用完就移除
  - `perf.ts` 在演出時量幀時間，低階手機自動降級：拿掉接觸陰影和光環、飛行縮短
